# МК-90 для Linux: C11 + LVGL 9.6.0 + X11

## Сборка и запуск

Зависимости: C/C++ toolchain (C++ нужен CMake-проекту LVGL), CMake >= 3.16,
Python 3 для подготовки картинок, заголовки X11, pthread и libm.
Код эмулятора написан на C.

Для Debian/Ubuntu:
```sh
  sudo apt install build-essential cmake python3 libx11-dev
```

Из папки mk90:
```sh
  cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
  cmake --build build -j
  ./build/mk90
```

LVGL берётся из локальной папки lvgl; сеть при сборке не используется.
Другой путь можно передать через -DMK90_LVGL_DIR=/path/to/lvgl-9.6.0.
Драйвер ввода привязан к устройству X11-драйвера этой версии LVGL.
В сеансе Wayland требуется XWayland и доступный DISPLAY.

После запуска появляется штатное меню прошивки. Enter (клавиша ВК на корпусе)
открывает выбранный пункт БЕЙСИК. Клавиши на корпусе нажимаются мышью.
Окно можно растягивать: корпус и области нажатия масштабируются вместе.

## Управление

Буквы и цифры: исходное соответствие клавиатуры Windows-эмулятора, латинская
раскладка компьютера. Переключение Р/Л внутри МК-90 — F7.

| Host key        | MK-90 key |
| --------------- | ---- |
| Enter           | ВК   |
| Backspace       | ЗВ   |
| Стрелки         | Стрелки МК-90   |
| Space           | Пробел          |
| PageUp/PageDown | Соответствующие нижние клавиши МК-90    |
| F2              | Переключить подписи над клавишами       |
| F3              | Открыть отладчик и остановить CPU |
| F5              | Сброс           |
| F6              | СУ              |
| F7              | Р/Л             |
| F8              | ФК              |
| F9              | В/Н             |
| Pause           | Приостановить/продолжить выполнение |

Верхняя красная клавиша завершает приложение, нижняя выполняет сброс.
Закрытие окна и SIGINT/SIGTERM также сохраняют изменённые карты СМП.
Удержание и отпускание клавиш обрабатываются отдельно; потеря фокуса
отпускает клавиши. Как в исходнике, одновременно опрашивается одна клавиша;
мышь имеет приоритет над физической клавиатурой.

## Отладчик

F3 открывает отдельное окно LVGL/X11. Для остановки сразу после запуска:

```sh
  ./build/mk90 --debugger
```

В окне доступны дизассемблер с подсветкой PC, регистры и флаги, просмотр
памяти байтами или словами. Можно выбрать карту адресов CPU, физическую RAM
или ROM. Просмотр устройств не вызывает побочных эффектов чтения шины.
Адреса и данные по умолчанию восьмеричные; переключатель позволяет выбрать hex.
Регистры и память пока доступны только для чтения.

Клавиши именно в окне отладчика:

| Клавиша | Действие |
| --- | --- |
| F5 | Продолжить |
| F6 | Один шаг |
| F7 | Выполнить N шагов (N задаётся десятичным числом) |
| F8 | Выполнить до выбранной строки дизассемблера |
| Pause | Остановить |
| Escape | Закрыть окно или отменить подтверждение |
| Ctrl+A | Выделить текст в поле ввода |

Поддерживаются 32 точки останова с отдельным включением и удалением.
Остановка происходит перед выполнением команды. После Continue текущая точка
пропускается один раз; при повторном попадании CPU снова остановится.
Длинное выполнение N шагов можно прервать кнопкой Pause. Шаг соответствует
одному вызову CPU: обработка прерывания или ожидание WAIT тоже занимают шаг.
Закрытие отладчика сохраняет текущий режим выполнения; F3 открывает его снова.

Внизу окна расположено управление SMP0/SMP1. На паузе выберите слот, введите
путь к бинарному образу и нажмите Load либо Export. Замена изменённой карты
и перезапись существующего файла требуют подтверждения. Ошибка загрузки
сохраняет прежнюю карту, экспорт записывает файл через временный файл.
Допустимый размер образа — от 1 байта до 16 МиБ; как в исходном эмуляторе,
карты меньше 64 КиБ считаются RAM, остальные ROM.

Загруженная карта помечается изменённой и при выходе сохраняется в state,
если не задан --no-save. Экспорт создаёт отдельную копию и не сбрасывает этот
признак. После замены карты может потребоваться сброс МК-90 — это зависит
от выполняемой программы. Поле пути пока поддерживает клавиатурный ввод ASCII.

## Образы и сохранение

В assets скопированы rom.bin, romt.bin, smp0.bin, smp1.bin и BMP из emul_src.
Исходные папки emul_src и emul не изменяются. rom.bin в них различается;
по умолчанию используется версия из emul_src (BASIC V2.0).

Образы в assets открываются только для чтения. Изменённые карты записываются
в state/smp0.bin и state/smp1.bin, через временный файл и rename. При следующем
запуске сохранённая карта имеет приоритет над начальным образом. Сброс не
перезагружает карту и не теряет несохранённые изменения. Путь state по умолчанию
закреплён при сборке внутри этого проекта, независимо от текущей папки запуска.

Примеры (из mk90):
```sh
  ./build/mk90 --ram 32 --speed 100000
  ./build/mk90 --assets ../emul --state-dir ./state-other
  ./build/mk90 --no-save
  ./build/mk90 --headless --seconds 3 --no-save --lcd build/lcd.pbm
  ./build/mk90 --seconds 5 --no-save --screenshot build/window.ppm
  ./build/mk90 --help
```

--assets меняет комплект ROM/СМП. Оформление встраивается при сборке из assets.
--state-dir должен существовать либо иметь существующую родительскую папку.
--no-save отключает и чтение сохранённых карт, и запись изменений.
--speed — бюджет инструкций в секунду, а не тактовая частота реального МК-90.
По умолчанию 100000: соответствует CpuSpeed=1000 при таймере 10 мс в исходнике.

## Проверки

```sh
  ctest --test-dir build --output-on-failure
```

Проверяются арифметика и флаги CPU, адресация, прерывания, карта памяти,
отложенные операции устройств, LCD, RTC, запуск ROM, вход в BASIC и сохранение
данных СМП. Тест ui_render рисует интерфейс LVGL без X-сервера.
Тест debugger проверяет точки останова, шаги, чтение памяти без побочных
эффектов, декодирование всех 65536 кодов команд и импорт/экспорт SMP.
debugger_render проверяет отрисовку окна отладчика без X-сервера.

Отдельный тест настоящего X11-окна (открывает окно примерно на 7 секунд):

```sh
  ./build/test_x11 ./build/mk90
  ./build/test_debug_x11 ./build/mk90
```

Он проверяет клавиатуру, мышь при масштабе 2x, сброс, F2, потерю фокуса,
закрытие окна и итоговый заголовок BASIC. Снимки остаются в указанной тестом
временной папке. Этот тест не входит в CTest, чтобы обычная проверка не
требовала графического сеанса.
Второй тест проверяет два окна, ввод пути, загрузку и экспорт SMP,
подтверждение и отмену замены, повторное открытие и завершение приложения.
Снимок отладчика также можно получить через --debug-screenshot build/debugger.ppm.

Сборка только ядра, без LVGL/X11/Python:

```sh
  cmake -S . -B build-core -DMK90_GUI=OFF
  cmake --build build-core -j
  ctest --test-dir build-core --output-on-failure
```

Проверка AddressSanitizer + UndefinedBehaviorSanitizer:
```sh
  cmake -S . -B build-sanitize -DMK90_GUI=OFF -DMK90_SANITIZE=ON
  cmake --build build-sanitize -j
  ctest --test-dir build-sanitize --output-on-failure
```

## Устройство проекта

| File              | Info                                      |
| ----------------- | ----------------------------------------- |
|  include/mk90.h   | Состояние машины и API независимого ядра |
|  src/cpu.c        | Декодирование, команды, адресация и прерывания |
|  src/devices.c    | RAM/ROM, системный контроллер, LCD, клавиатура, СМП, RTC |
|  src/storage.c    | Загрузка образов, сохранение карт, выгрузка LCD |
|  src/main.c       | Параметры запуска и режим без графики |
|  src/ui.c         | Корпус, кнопки и LCD на LVGL |
|  src/debugger.c   | Управление выполнением и точки останова |
|  src/disasm.c     | Дизассемблер PDP-11 |
|  src/debug_ui.c   | Окно отладчика и управление образами SMP |
|  src/x11_host.c   | Штатный X11-дисплей LVGL и ввод для эмулятора |
|  tools/artwork.py | Преобразование палитровых BMP в массивы изображений LVGL |
|  lv_conf.h        | Конфигурация LVGL, программная отрисовка, X11 без SDL |

CPU, периферия и UI обслуживаются последовательно; поток X11-драйвера LVGL
ведёт только его счётчик времени. Скорость CPU не зависит от частоты перерисовки.
LCD извлекается из RAM с исходным чередованием байтов двух половин экрана.

## Границы первой версии

Перенесён пользовательский режим с корпусом и клавиатурой; добавлен
отладчик. Редактирование памяти и регистров, ассемблер, шаг через вызов
и точки останова на доступ к памяти пока не реализованы.
Модель функциональная, не потактовая. Поддержка аппаратуры соответствует
исходнику: LCD реализует адрес видеопамяти; задержки последовательной шины
не моделируются; FIS вызывает trap, а не аппаратные операции с плавающей точкой.

RTC инициализируется местным временем при запуске/сбросе. Загрузка rtc.bin
отключена, как в публичном Pascal-исходнике. Календарная арифметика исправлена:
BCD, переход года, високосный февраль, 12/24-часовой режим. Время RTC во время
работы следует времени эмуляции и останавливается при Pause. Длительные
задержки хоста ограничены, чтобы интерфейс не зависал на догоняющем выполнении.

В C устранены зависимость от выравнивания указателей и неопределённые
переполнения/сдвиги. Пограничные сдвиги ASHC на 32 разряда определены явно.
Тесты не доказывают полную эквивалентность каждой команды реальному МК-90;
сравнительное выполнение всех команд с Windows-версией ещё не проводилось.

## Происхождение

Перенос основан на предоставленных исходниках emul_src (журнал изменений:
version 22, 2022/02/01). Модули CPU/адресации исходника указывают основу —
эмулятор PDP-11/03 Овсиенко В. А. ROM и оформление взяты из того же комплекта.
Новая лицензия на исходные ROM, изображения и Pascal-код здесь не назначается.
Таблица команд дизассемблера перенесена из pdp11dis.pas, где указаны
Martin Minow и pinst.c.
